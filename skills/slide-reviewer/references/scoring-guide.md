# 採点ガイド

## スコアの扱い

内容と見た目を別々に100点満点で採点する。総合点を出す場合は、両者の単純平均を参考値として示し、個別スコアを必ず併記する。採点は絶対的な品質保証ではなく、改善箇所を比較するための目安である。

情報が不足している項目は、根拠なく満点・減点せず「評価保留」とする。評価保留がある場合は、保留した評価軸の配点を除いた得点を100点満点に換算し、保留した評価軸と採点の確度が低いことを明記する（例: 90点満点中72点 → 80点、「聴衆との適合・発表設計」は持ち時間不明のため保留）。

## 内容レビュー（100点）

| 評価軸 | 配点 | 確認内容 |
|---|---:|---|
| 目的・読者・メッセージ | 15 | 誰に何を伝えるか、持ち帰るメッセージ |
| ストーリー・構成 | 20 | 導入、展開、スライド間の接続、結論 |
| 聴衆との適合・発表設計 | 10 | 持ち時間と枚数、導入の長さ、分量の配分（content-review.md 4.5） |
| 論理・根拠 | 20 | 主張と根拠の対応、飛躍、比較条件 |
| 情報の過不足 | 15 | 前提、説明順序、情報量、重複 |
| 技術説明 | 15 | コード・図・仕組み・具体例の説明 |
| まとめ・行動 | 5 | 結論の回収、次の行動や学び |
| **合計** | **100** | |

## 見た目レビュー（100点）

| 評価軸 | 配点 | 確認内容 |
|---|---:|---|
| 視認性 | 25 | 文字サイズ、コントラスト、色覚特性、投影耐性 |
| 情報の階層・密度 | 20 | 優先順位、情報量、余白 |
| レイアウト・視線誘導 | 20 | 整列、配置、読む順序 |
| 図表・コードの可読性 | 20 | 図、グラフ、コード、ログの読み取りやすさ |
| 一貫性 | 10 | フォント、色、装飾、パターン |
| 投影時の実用性 | 5 | 会場での読みやすさ、表示崩れ、アニメーション依存 |
| **合計** | **100** | |

## 点数の目安

| 点数 | 評価 | 意味 |
|---:|---|---|
| 90–100 | 非常に良い | 大きな問題がなく、細かな改善が中心 |
| 80–89 | 良い | 発表として十分成立し、いくつか改善余地がある |
| 70–79 | 要改善 | 理解や視認性を妨げる問題が複数ある |
| 60–69 | 大幅な改善が必要 | 構成や表示に発表の成立を妨げる問題がある |
| 0–59 | 再設計を推奨 | 目的・構成・可読性の根本的な見直しが必要 |

## 採点時の注意

- まず全体を評価し、個別スライドの指摘数をそのまま減点数にしない。
- 同じ根本原因から生じる複数の症状は、重複して大きく減点しない。
- 好みの問題、資料から確認できない口頭説明、会場条件を推測して減点しない。
- 発表時間・対象読者が不明なら、その条件に依存する評価は保留する。
- PDF画像を確認できず、ソースだけを見た見た目レビューは確度を下げ、実表示に関する項目を評価保留にする。
- 点数の理由を短く説明し、数値だけで終わらせない。
